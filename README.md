## Áreas de enfoque

### Análisis de requisitos

Caracterizar el proceso o la necesidad, recoger información con el usuario y distinguir requisitos funcionales de requisitos no funcionales. El análisis es la base para que el diseño y el código respondan a un problema real y no a una suposición.

### Diseño de la solución

Modelar la solución antes de construirla: casos de uso, flujos, estructura de datos y criterios de la arquitectura (qué hace cada parte del sistema y cómo se relacionan). Un diseño legible facilita el desarrollo, las pruebas y el mantenimiento.

### Desarrollo de software

Traducir el diseño en una aplicación que funcione: lógica de programación, interfaces, persistencia de datos e integración entre componentes. Priorizo código comprensible, acorde con la metodología de trabajo del equipo.

### Calidad, implementación y documentación

Definir qué se va a probar, ejecutar pruebas y registrar resultados. La entrega incluye lo necesario para operar la solución: manuales, evidencias y trazabilidad entre el requisito y lo construido.
